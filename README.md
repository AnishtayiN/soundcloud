# ساندکلاد ایکس — SoundCloud X

برنامهٔ غیررسمی جستجو، پخش و دانلود ساندکلاد برای اندروید و ویندوز.

## برای استفاده، پایتون نصب نکنید

از [Releases](https://github.com/AnishtayiN/soundcloud/releases) **فایل اجرایی** بگیرید، نه `Source code.zip` و نه `main.py`:

| دستگاه | فایل | روش استفاده |
|---|---|---|
| ویندوز ۶۴بیتی | `SoundCloudX-Setup-<version>-x64.exe` | نصب‌کنندهٔ کامل؛ آفلاین نصب می‌شود، میان‌بر و حذف‌کننده دارد |
| ویندوز پرتابل | `SoundCloudX.exe` | مستقیم اجرا کنید؛ نصب پایتون، pip، Tcl یا کتابخانه لازم نیست |
| اندروید ۷ به بالا | `SoundCloudX-<version>.apk` | فایل APK را نصب کنید؛ اجازهٔ نصب از منابع ناشناس برای مرورگر/فایل‌منیجر لازم است |

**پایتون و ابزارهای ساخت فقط برای توسعه‌دهندگان این مخزن هستند.** مفسر پایتون، Tcl/Tk، تم‌ها و فونت‌های CustomTkinter، Pillow، گواهی‌های TLS و موتور صوتی SDL/pygame در EXE قرار می‌گیرند. نصب‌کننده هم همین EXE را همراه مجوز در سیستم قرار می‌دهد و چیزی از اینترنت نصب نمی‌کند. اینترنت برای ارتباط با ساندکلاد لازم است، نه برای راه‌اندازی برنامه.

EXE فعلاً امضای تجاری ویندوز ندارد؛ ممکن است SmartScreen هشدار بدهد. هش فایل را با `SHA256SUMS.txt` همان انتشار مقایسه کنید؛ فقط پس از اطمینان از منبع، اجازهٔ اجرا بدهید. آنتی‌ویروس را خاموش نکنید.

### چرا APK قدیمی ۱۱۹ کیلوبایت بود؟

نسخهٔ قبلی فقط از کلاس‌های خود اندروید استفاده می‌کرد و موتور پخش جداگانه‌ای در APK نداشت. کوچک بودن فایل، به‌تنهایی، ثابت نمی‌کند ناقص یا کامل است. وعدهٔ «حدود ۱ مگابایت» در مستندات قبلی اندازه‌گیری نشده بود و حذف شده است.

نسخهٔ جدید **Media3/ExoPlayer و پشتیبانی HLS را داخل APK** بسته‌بندی می‌کند؛ میان‌بر سایت نیست و موتور را هنگام اولین اجرا دانلود نمی‌کند. فایل با دادهٔ بی‌مصرف بزرگ نشده است. اندازه، SHA-256 و اجزای واقعاً تست‌شدهٔ هر انتشار در `build-info.json` ثبت می‌شود؛ خروجی‌ها تنها پس از عبور از تست اجرای فایل نهایی منتشر می‌شوند.

## اصلاحات بسته‌بندی و اجرا

* حذف اشتباه `email`، `PIL.ImageTk` و اجزای ضروری از PyInstaller برداشته شد؛ منابع تم، فونت، گواهی و فایل‌های صوتی صریحاً جمع‌آوری می‌شوند.
* **خود EXE ساخته‌شده** و نسخهٔ نصب‌شده، با PATH بدون پایتون/Tcl و از پوشهٔ خالی با نام فارسی اجرا می‌شوند؛ باز شدن پنجرهٔ واقعی، تصویر، منابع و DLL صوت، اجرای عادی و خروج سالم بررسی می‌شود.
* خطای شروع ویندوز حتی اگر Tk خراب باشد با پیام بومی ویندوز و گزارش محلی نشان داده می‌شود، نه پنجرهٔ بی‌صدا یا درخواست نصب پایتون.
* مشکل ثبت گیرنده روی Android 14+ اصلاح شده؛ گیرندهٔ مدیا در Manifest تعریف شده و پیام‌های وضعیت محدود به خود برنامه‌اند.
* پخش اندروید از Media3 استفاده می‌کند؛ سرویس قبل از گرفتن لینک شبکه وارد foreground می‌شود، کنترل هدست/بلوتوث و نوتیفیکیشن دارد.
* پخش از **transcodingهای اعلام‌شدهٔ خود ساندکلاد** انتخاب می‌شود، نه فقط URL حدسی. MP3 مستقیم یا HLS کامل و رمزگذاری‌نشده پشتیبانی می‌شود.
* دانلود HLS قطعه‌ها را به فایل صوتی تبدیل می‌کند؛ خود `m3u8`، پاسخ HTML/JSON یا فایل ناقص را به اسم MP3 ذخیره نمی‌کند.
* اندروید از سرویس دانلود با پیشرفت و لغو استفاده می‌کند؛ Android 10+ با `MediaStore` و `IS_PENDING`، و Android 7–9 با فایل موقت، انتشار نهایی و `FileProvider`. `DownloadManager` مقصد `content://` را قبول نمی‌کرد؛ این مسیر اشتباه حذف شده است.
* انتخاب **Original** در صورت نبود اجازهٔ ناشر/حساب خطا می‌دهد؛ MP3 ۱۲۸ به‌جای فایل اصلی تحویل نمی‌شود.
* نتیجهٔ درخواست قدیمی، صفحهٔ علاقه‌مندی یا جستجوی جدید را بازنویسی نمی‌کند؛ کوکی ورود نیز به CDNهای صوت/تصویر نشت نمی‌کند.

## امکانات

* جستجوی نام آهنگ/خواننده و باز کردن لینک آهنگ یا پلی‌لیست ساندکلاد
* ترندها و انتخاب سبک، کاور، عنوان، زمان و seek
* علاقه‌مندی‌ها، صف پخش، کپی/اشتراک لینک و باز کردن در مرورگر
* دانلود MP3 و فایل اصلی مجاز؛ تاریخچه و نمایش وضعیت/لغو
* اندروید: پخش پس‌زمینه، MediaSession، کنترل مدیا و ذخیره در `Music/SoundCloudX`
* ویندوز: کش پخش، تنظیم صدا، پوشهٔ دانلود قابل انتخاب، رابط فارسی/English
* ورود اندروید با WebView سایت؛ ویندوز با کوکی حساب صادرشده از مرورگر (`cookies.txt`، شامل HttpOnly). کوکی حساب را عمومی منتشر نکنید.

کشف `client_id` عمومی از سایت و کش آن انجام می‌شود. این API غیررسمی است و ساندکلاد می‌تواند آن را تغییر دهد، محدود یا مسدود کند؛ وعدهٔ اتصال همیشگی یا دانلود همهٔ آهنگ‌ها نداریم. آثار مسدود، DRM، پیش‌نمایش یا فایل اصلی بدون اجازه، به‌عنوان آهنگ کامل دانلود نمی‌شوند.

## تست‌ها و محدودهٔ واقعی پشتیبانی

ورک‌فلو `Build & Release` شامل این مراحل است:

1. نسخهٔ یکسان و معتبر برای APK، EXE و نصب‌کننده.
2. تست منطق آفلاین ویندوز و ساخت پنجرهٔ واقعی؛ بعد از بسته‌بندی دوباره تست **داخل EXE** و نصب‌کننده، بدون Python در PATH.
3. تست واحد HLS جاوا، lint، ساخت APK، بررسی منابع/کد Media3، امضا و غیر-debug بودن خروجی release.
4. نصب و شروع/ازسرگیری **APK release** روی شبیه‌سازهای API **24، 34، 36** (اندروید **۷، ۱۴، ۱۶**)؛ پنج تست واقعی رابط، علاقه‌مندی، اجزای سرویس، پخش WAV محلی و ذخیره‌سازی روی هر کدام.
5. ساخت `SHA256SUMS.txt` و `build-info.json`؛ انتشار فقط اگر تمام موارد بالا سبز باشند. گزارش‌های شکست در Artifacts نگه داشته می‌شوند.

**این تست‌ها آفلاین‌اند:** اتصال زندهٔ ساندکلاد، ورود به حساب، حقوق دسترسی به هر آهنگ و شبکه/دستگاه شما را تضمین نمی‌کنند. ویندوزِ تست CI، Windows Server 2022 است. Python 3.8/PyInstaller 5 برای حفظ سازگاری رانتایم با Windows 7 SP1 و 8.x حفظ شده‌اند، ولی آن سیستم‌های پایان‌عمر‌یافته در CI تست نشده‌اند؛ ویندوز ۱۰/۱۱ توصیه می‌شود. «همهٔ نسخه‌ها کاملاً تست شده‌اند» ادعای درستی نیست.

## امضای اندروید و ارتقا

امضای انتشار قبلی در هر اجرای CI از نو ساخته و سپس دور ریخته می‌شد؛ بنابراین وعدهٔ قبلیِ «همهٔ آپدیت‌ها روی نسخهٔ قبلی نصب می‌شوند» اشتباه بود.

برای انتشار پایدار، مالک پروژه باید این Secrets را **در GitHub، نه در چت یا Git** تنظیم و از کلید اصلی نسخهٔ پشتیبان نگه دارد:

* `ANDROID_KEYSTORE_BASE64`
* `ANDROID_KEYSTORE_PASSWORD`
* `ANDROID_KEY_ALIAS`
* `ANDROID_KEY_PASSWORD`

بدون آنها APK با **کلید توسعهٔ کش‌شده** امضا و انتشار خودکار **pre-release** می‌شود؛ حذف کش یا تغییر شاخه می‌تواند کلید توسعه را عوض کند. fingerprint عمومی در `android-signature.txt` قرار دارد. اگر نصب می‌گوید امضا ناسازگار است، ارتقای مستقیم ممکن نیست؛ قبل از حذف نسخهٔ قبلی، داده‌های مهم را نگه دارید (حذف برنامه علاقه‌مندی‌ها و ورود را پاک می‌کند). داشتن کلید ثابت برای آپدیت مسئولیت سازنده است، نه نیازِ استفاده‌کننده.

## ساخت برای توسعه‌دهندگان

### اندروید

JDK 17، Android SDK 34، Gradle Wrapper و اینترنت برای دریافت ابزارها/وابستگی‌ها لازم است:

```sh
cd android
./gradlew :app:testDebugUnitTest :app:lintRelease :app:assembleRelease
```

کلید امضا از متغیرهای محیطی `KEYSTORE_FILE`، `KEYSTORE_PASSWORD`، `KEY_ALIAS`، `KEY_PASSWORD` می‌آید. ساخت محلی بدون آنها با debug key امضا می‌شود و انتشار پایدار محسوب نمی‌شود. نسخه را با `-PappVersionName=1.0.1 -PappVersionCode=100` تعیین کنید.

### ویندوز

به [windows/README.md](windows/README.md) مراجعه کنید. ساخت EXE ویندوز باید **روی ویندوز** انجام شود؛ PyInstaller لینوکس، EXE ویندوز تولید نمی‌کند.

### ساخت و دریافت با GitHub Actions

از Actions → Build & Release → Run workflow، شاخه و نسخهٔ `major.minor.patch` را انتخاب کنید. بعد از پایان تمام تست‌ها، سه فایل نصبی/اجرایی به‌همراه گزارش و هش در Releases قرار می‌گیرند. اگر workflow قرمز است، آن اجرا نسخهٔ قابل تحویل تولید نکرده و نباید آن را کامل معرفی کرد.

## گزارش خطای ویندوز

نصب‌کننده میان‌بر **Run offline diagnostics** در Start Menu ایجاد می‌کند؛ به پایتون نیاز ندارد. نتیجه در `%APPDATA%\SoundCloudX\self-test.json` و خطای شروع در `%LOCALAPPDATA%\SoundCloudX\logs\startup.log` است. گزارش تست، کوکی یا تنظیمات حساب را شامل نمی‌شود. فقط گزارش لازم را ارسال کنید، نه `settings.json` یا `cookies.txt`.

این پروژه متن‌باز و غیررسمی است و با SoundCloud ارتباط سازمانی ندارد. فقط آثاری را دانلود کنید که اجازهٔ دریافت/استفاده از آنها را دارید.

پوش به شاخه‌های `arena/**` نیز ساخت و پیش‌انتشار تست‌شده را فعال می‌کند؛ فایل از همان commit ساخته می‌شود، نه از main. این مسیر برای دسترسی‌هایی است که Run workflow را اجازه نمی‌دهند.
